Инструкция по запуску Дополнения к Лабораторной работе №1 (Миграция на SQLite)
Чтобы всё работало корректно, выполни эти 5 простых шагов. Оставлять файл init_db.php в папке проекта безопасно — он поможет быстро развернуть или сбросить базу данных.

Шаг 1. Размещение файлов
Распакуй папку с проектом в директорию твоего локального веб-сервера (OpenServer).

Если у тебя старая версия OpenServer (5.x), это папка OSPanel\domains.

Если новая (6.0), это папка OSPanel\home.

Здесь не забудь создать папку surgdbidz.local, это обязательно, и закинь туда все файлы (включая init_db.php и пустой файл базы данных, если он есть):

Шаг 2. Развертывание и заполнение базы данных (ОБЯЗАТЕЛЬНО)
Так как СУБД SQLite хранит все таблицы и данные в одном локальном файле прямо внутри проекта, тебе не нужно заходить в phpMyAdmin или настраивать MySQL.

Запусти OpenServer.

Открой браузер и перейди по специальному адресу инициализации: http://surgdbidz.local/init_db.php.

На экране появится сообщение о том, что база данных SQLite успешно создана и заполнена тестовыми данными. В этот момент в папке проекта автоматически запишется рабочий файл clinic_duty.db.

Шаг 3. Настройка подключения (db.php)
Благодаря технологии PDO, настройки подключения стали универсальными и независимыми от версий OpenServer или XAMPP. Открой файл db.php в любом редакторе, чтобы убедиться в конфигурации. Путь к файлу базы данных вычисляется автоматически:

PHP
$db_path = __DIR__ . '/clinic_duty.db';
$dsn = "sqlite:$db_path";
Никаких хостов, портов, логинов и паролей изменять больше не требуется.

Шаг 4. Запуск
Запусти проект (или перезапусти OpenServer, чтобы он гарантированно применил конфигурацию новой папки). Открой браузер и перейди по локальному адресу проекта: http://surgdbidz.local.

🛠 Частые ошибки:
Списки полностью пустые при первом запуске: Ты забыла запустить скрипт развертывания таблиц. Просто перейди по адресу http://surgdbidz.local/init_db.php один раз для генерации структуры.

Ошибка "unable to open database file": Убедись, что у папки surgdbidz.local есть права на запись, чтобы веб-сервер мог создать и изменять файл clinic_duty.db внутри неё.
